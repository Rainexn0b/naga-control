# v0.4.0 Release Preparation

> **Historical snapshot:** Retained from before v0.4.0 publication.
> Not current release instructions. Unchecked items remain unresolved
> evidence, not new passes.

This is a preparation checklist, not release notes or approval to publish.
The source package version is `0.4.0`; `changelog.md` remains **Unreleased**
until the scope and UTC publication date are settled. The README's pinned
install command must continue to use published `v0.3.0` until then.

## Gates

- [ ] Resolve work still in progress, especially the UI-06 device-mode handoff.
  Its tray control is withheld pending held-output and wireless wake hardware
  validation; see [Hardware Validation](hardware-validation.md) and the
  [UI tracker](post-0.3-ui-tracker.md). If deferred, do not ship an unvalidated
  service mode transition or claim that it is supported in release notes.
- [ ] Verify the KDE Plasma/Wayland desktop-file identity and single-instance
  behavior on the reported Debian 13 / MX Linux setup, both from a source venv
  and from the AppImage. Fully exit older GUI processes before testing.
- [ ] Recheck wired and HyperSpeed service behavior separately after final
  changes. Run opt-in hardware tests only with the documented safety setup.
- [ ] Review all **Unreleased** changelog claims against the final diff and
  validation evidence. Move the finalized items into exactly one dated
  `## [0.4.0] - YYYY-MM-DD` section using the actual UTC publication date;
  leave any unfinished items under a fresh **Unreleased** section.
- [ ] Review the dirty worktree and stage only intended source, tests, and
  documentation. Keep raw hardware captures, local logs, and secrets out of
  the release commit.
- [ ] Update `docs/release-notes.md` and the README's pinned install example
  only when v0.4.0 is ready to ship. Retain the exact custom OpenRazer
  prerequisite, supported USB IDs, and one-transport limit in release notes.

## Preflight

Run before deciding to tag:

```bash
ruff check .
ruff format --check .
pyright
pyright scripts/prepare_release.py
pytest
python scripts/prepare_release.py v0.4.0 --notes-output /tmp/opencode/v0.4.0-notes.md
python -m buildpython --profile release
```

The release-notes command must fail until the dated changelog section exists;
that is intentional. Inspect its output and the AppImage's bundled version and
GUI assets after it succeeds. Do not create or push `v0.4.0`, open a GitHub
release, or upload artifacts until release approval: pushing a `v*` tag
automatically runs `.github/workflows/release.yml` and publishes the release.
